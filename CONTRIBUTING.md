# Contributor Excellence Framework

sloppy-toppy operates at the frontier of AI-native system observation. We hold our contributors to the same standard of excellence that defines our shame-delivery culture.

---

## What We're Actually Building

sloppy-toppy is a terminal system monitor. It shows CPU, memory, swap, network, disk, and temperature. It also routes your machine's vitals through an LLM so that LLM can say something sexually suggestive about your `ollama` process.

Contributions should make the monitoring better, the roasts meaner, or the innuendo more specific.

---

## Code Authorship

sloppy-toppy does not accept handwritten code. All contributions must be generated by a large language model.

We enforce **tokenmaxxing**: contributions are evaluated in part by token density. Sparse, human-legible code suggests insufficient model engagement. A well-contributed function should require a non-trivial inference budget to produce.

If you wrote it yourself, it isn't ready.

---

## Variable Naming

Tokenmaxxing extends to identifiers. Single-letter variables, `tmp`, `x`, and `i` are not permitted. Every identifier must carry its full semantic weight.

| Banned | Approved |
|--------|----------|
| `i` | `iterationIndexVector` |
| `tmp` | `ephemeralComputationArtifact` |
| `err` | `remediationOpportunity` |
| `snap` | `systemVitalsSnapshotArtifact` |
| `cfg` | `providerConfigurationSubstrate` |

If a model didn't generate it, it probably isn't verbose enough.

## Adding a New Provider

sloppy-toppy supports Ollama, Anthropic, and OpenAI-compatible endpoints. To add a new provider:

1. Add a variant to the `provider` match in `src/joke.rs`
2. Implement `fetch_roast_yourprovider(snap: &Snapshot, cfg: &JokeConfig) -> Result<String, String>`
3. Add the relevant fields to `JokeConfig` and `Config`
4. Document the new env vars and config keys in `README.md`

The fetch function must return a single sentence. The `clean()` function will truncate at the first `.!?` regardless, so the model doesn't need to comply — but it should try.

---

## Adding a New Metric

Metrics live in `src/metrics.rs`. To add a new one:

1. Add the field to `Snapshot`
2. Collect it in `Collector::sample()`
3. Add a panel to `draw_meters()` in `src/ui.rs`
4. Include the value in `build_prompt()` in `src/joke.rs` so the LLM can mock it

Keep the prompt compact. Small local models (phi3, llama3.2) choke on long contexts and start returning 500s. If it doesn't fit in one line of stats, it probably shouldn't be in the prompt.

## Running the CI Pipeline

CI runs automatically on push to `main` and on pull requests. It builds and lints on Linux, macOS, and Windows.

To trigger a release manually, go to **Actions → Release → Run workflow** and enter the tag (e.g. `v0.2.0`). This builds and uploads binaries for all four targets. Alternatively, push a `v*` tag and it fires automatically.

```sh
git tag v0.2.0
git push --tags
```

## Configuration for Local Development

```sh
# Ollama (default — no API key needed)
SLOPPY_MODEL=llama3.2 cargo run

# Anthropic
SLOPPY_PROVIDER=anthropic ANTHROPIC_API_KEY=sk-ant-... cargo run

# OpenAI-compatible
SLOPPY_PROVIDER=openai OPENAI_API_KEY=sk-... cargo run
```

Config file (optional): `~/.config/sloppy-toppy/config.toml`

```toml
provider = "ollama"
model = "llama3.2"
roast_interval_secs = 15
alert_cpu = 90.0
alert_mem = 90.0
```
